# 得到笔记卡片 — 录音文件传输协议完全破解

> **结论：录音文件传输是明文的，不需要 AES 密钥，不需要手机 App，可以完全离线自主下载。**

---

## 一、突破点

之前判断"数据通道 `0xA102/0xA105` 是 AES 加密"，这是**只对短命令通道成立**。

真实情况是**双通道分工**：

| 通道 | 用途 | 加密 |
|---|---|---|
| `0xA102` / `0xA105` | 短命令、状态轮询（16B 定长块） | ✅ AES |
| `0xA202` / `0xA205` | **控制命令 + 录音文件传输** | ❌ **完全明文** |

抓包证据 —— 文件名和数据都在明文里：

```
NOTIFY 0xA205:  fcfcfcfc 4300 3400  31 2c 323032362d31302d31302d31342d31342d33372e6f6767...
                └magic┘ └cmd┘ └len┘  └"1,2026-10-10-14-14-37.ogg..."┘   ← 明文文件名

NOTIFY 0xA205:  fcfcfcfc 4503 dc01  d8010000  4f676753 0002 ...
                └magic┘ └cmd┘ └len┘ └offset┘  └"OggS"┘                  ← 明文 Ogg 音频
```

## 二、文件传输协议（完整）

**帧格式（控制通道，LE）：**
```
magic(4)=fcfcfcfc + cmd(2 LE) + len(2 LE) + body(len) + crc32(4 LE)
```

| cmd | 方向 | body 结构 | 语义 |
|---|---|---|---|
| `0x0043` | ← 设备 | ASCII `idx,文件名,yyyy-mm-dd HH:MM:SS,字节数;` | **文件列表** |
| `0x0145` | → 设备 | `00000000` + 文件名字符串 | **请求下载文件** |
| `0x0245` | ← 设备 | `size(4 LE)` + … | 文件信息（声明大小） |
| `0x0345` | ← 设备 | **`offset(4 LE)` + data(≤472 B)** | **★ 文件数据块** |
| `0x0445` | ← 设备 | 4 字节 | 传输结束 |
| `0x0150` | ← 设备 | 16 条 | 进度/确认 |
| `0x0146` | ↔ | ASCII 时间戳 | 时间同步 |
| `0x0000` / `0x0050` | ↔ | — | 查询/心跳 |
| `0x0043` (写) | → | `01000000 05000000` | 参数设置 |

---

## 三、★ 关键细节：`offset` 是「块结束位置」

这是最容易踩的坑。

**数据块 body = `offset(4 LE)` + data**，其中 **`offset` 表示该块写完后文件已到达的字节位置**（即结束位置），不是起始位置。

**判定依据（铁证）：**
```
文件1 声明大小 = 31843
offset 序列末尾 = 31843      ← 分毫不差
文件2 声明大小 = 51562
offset 序列末尾 = 51562      ← 分毫不差
```

**写入位置 = `offset - len(data)`。**

如果误当成"起始位置"，重建出的文件开头会是**全零**（因为第一块 offset=472，会写到 472 处，0..471 空着）。
